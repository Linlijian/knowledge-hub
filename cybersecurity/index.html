บทที่ 1

พื้นฐาน & แนวคิดหลักของ Cyber Security

ก่อนจะไปดูว่าใครโจมตีเราด้วยวิธีไหน ต้องตกลงคำศัพท์ให้ตรงกันก่อน บทนี้ปูสามเรื่องที่ข้อสอบชอบถามมากที่สุด — เราปกป้อง อะไร (CIA Triad), เราควบคุม ใคร (AAA) และคำที่หน้าตาคล้ายกันจนสับสน (Threat / Vulnerability / Risk)

🛡️ Cyber Security คืออะไร

คือการปกป้องระบบคอมพิวเตอร์ เครือข่าย โปรแกรม และข้อมูล จากการเข้าถึง ใช้งาน เปิดเผย แก้ไข หรือทำลายโดยไม่ได้รับอนุญาต

จุดที่คนมักเข้าใจผิดคือคิดว่ามันเป็นเรื่องของเครื่องมือหรือซอฟต์แวร์อย่างเดียว ความจริงมันประกอบด้วยสามขาเสมอ — People (คน), Process (กระบวนการ) และ Technology (เทคโนโลยี) ขาที่พังบ่อยที่สุดคือขาแรก

🎯 ทำไมต้องเรียนเรื่องนี้

  • ทุกอย่างต่อเน็ตหมดแล้ว — ตั้งแต่กล้องวงจรปิดถึงระบบควบคุมโรงงาน
  • ต้นทุนการโจมตีถูกลง — ผู้โจมตีเช่าเครื่องมือเป็นบริการรายเดือนได้
  • ความเสียหายไม่ใช่แค่เงิน — ยังมีเรื่องความเชื่อมั่นและกฎหมายคุ้มครองข้อมูล
  • ป้องกันถูกกว่าตามแก้ — งบ patch ราคาถูกกว่าค่ากู้ระบบหลังถูก ransomware มาก

🔗 เชื่อมกับความรู้เครือข่ายเดิม

ถ้าเคยเรียน OSI Model มาแล้ว จะได้เปรียบมากในวิชานี้ เพราะการโจมตีเกือบทุกแบบ เกิดขึ้นที่ชั้นใดชั้นหนึ่งของ OSI เสมอ

บทที่ 3 ของเว็บนี้จะพาไล่ทั้ง 7 ชั้นว่าแต่ละชั้นถูกโจมตีอย่างไร และต้องกันที่อุปกรณ์ตัวไหน

ตารางเปรียบเทียบ: Cyber vs Network vs Information Security

สามคำนี้ถูกใช้สลับกันบ่อยมากในชีวิตจริง แต่ในข้อสอบมันมีขอบเขตที่ต่างกันชัดเจน

ศาสตร์ ขอบเขตที่ดูแล ปกป้องอะไร ตัวอย่างมาตรการ ข้อสังเกต

CIA Triad — สามเสาหลักที่ต้องท่องให้ขึ้นใจ

คลิกที่มุมใดมุมหนึ่งของสามเหลี่ยม เพื่อดูคำอธิบายและเหตุการณ์จริงที่เสานั้นล้มเหลว

➕ หลักเสริมที่มักถูกถามต่อ

    ⚖️ สามเสานี้ขัดกันเองได้

    เพิ่ม Confidentiality ด้วยการเข้ารหัสหนัก ๆ และบังคับยืนยันตัวตนหลายชั้น มักทำให้ Availability ลดลง (ใช้งานยากขึ้น ช้าลง) งานของทีมความปลอดภัยคือหา จุดสมดุล ที่เหมาะกับความเสี่ยงขององค์กรนั้น ไม่ใช่ดันสุดทางด้านใดด้านหนึ่ง

    AAA + Non-repudiation — อธิบายด้วยสถานการณ์ธนาคาร

    ทั้งสี่คำนี้เป็นคนละขั้นตอนกัน ลองไล่ตามลำดับการใช้แอปธนาคารหนึ่งครั้ง

            บทที่ 3 · หัวใจของวิชานี้

            การโจมตีที่โยงกับ OSI Model

            นี่คือบทที่เชื่อมความรู้ “เครือข่าย” กับ “ความปลอดภัย” เข้าด้วยกันชัดที่สุด โครงเดียวกับ OSI 7 Layer ที่เคยเรียน แต่คราวนี้แต่ละชั้นจะบอกว่า ถูกโจมตีด้วยวิธีไหนได้บ้าง และ ต้องไปวางการป้องกันที่ตรงไหน

            คลิกที่ชั้นเพื่อกางดูการโจมตี แล้วคลิกที่ชื่อการโจมตีเพื่อดูหลักการ ผลกระทบ และวิธีป้องกัน

            ทำไม Network กับ Security ถึงแยกกันไม่ออก

            สรุปที่ต้องจำให้ได้: การโจมตีชั้นล่าง (L1–L2) มักต้องเข้าถึงพื้นที่หรืออยู่ในวง LAN เดียวกัน แต่ถ้าทำได้จะกวาดทราฟฟิกได้ทั้งวง · การโจมตีชั้นบน (L7) ทำได้จากทุกที่ในโลกผ่านอินเทอร์เน็ต จึงพบมากที่สุดในทางปฏิบัติ · ส่วน L3–L4 คือชั้นที่การโจมตีแบบ DoS/DDoS อาศัยอยู่
            บทที่ 4

            มัลแวร์ (Malware)

            Malware มาจาก Malicious + Software คือซอฟต์แวร์ที่ถูกเขียนขึ้นเพื่อสร้างความเสียหาย จุดที่ข้อสอบชอบถามที่สุดไม่ใช่ชื่อ แต่คือ “มันแพร่กระจายอย่างไร” และ “ต้องพึ่งไฟล์เจ้าบ้านกับการกระทำของผู้ใช้หรือไม่”

            คลิกที่การ์ดเพื่อสลับดูรายละเอียดแบบเต็ม

            ตารางเปรียบเทียบมัลแวร์ 10 ชนิด

            ชนิด วิธีแพร่กระจาย ต้องมี host? ต้องมีคนกด? เป้าหมายหลัก ตัวอย่างที่รู้จักกัน

            Virus เทียบกับ Worm — ข้อที่ออกสอบบ่อยที่สุด

            กดปุ่มเพื่อดูลำดับการแพร่กระจายของทั้งสองแบบทีละขั้น

            ข้อควรรู้: ในโลกจริงมัลแวร์ตัวหนึ่งมักเป็นหลายชนิดผสมกัน เช่น WannaCry เป็นทั้ง Worm (แพร่เองผ่านช่องโหว่) และ Ransomware (เข้ารหัสไฟล์เรียกค่าไถ่) การแบ่งชนิดจึงเป็นการแบ่งตาม “พฤติกรรมเด่น” ไม่ใช่กล่องที่แยกขาดจากกัน
            บทที่ 5

            Social Engineering — โจมตีที่ “คน” ไม่ใช่ที่ระบบ

            ไม่ต้องเจาะ firewall ถ้าหลอกให้คนเปิดประตูให้เองได้ Social Engineering คือการใช้จิตวิทยาหลอกให้เหยื่อทำสิ่งที่ผู้โจมตีต้องการ และเป็นต้นทางของเหตุการณ์ความปลอดภัยส่วนใหญ่ในโลกจริง

            🧠 จิตวิทยาที่ถูกใช้เป็นอาวุธ

            • อำนาจ (Authority) — อ้างเป็นผู้บริหาร ตำรวจ หรือฝ่ายไอที
            • ความเร่งด่วน (Urgency) — บีบเวลาจนเหยื่อไม่ทันได้คิด
            • ความกลัว (Fear) — ขู่ว่าบัญชีจะถูกระงับหรือจะมีความผิด
            • ความอยากรู้ (Curiosity) — หัวข้อที่ยั่วให้ต้องเปิดดู
            • ความเกรงใจ (Social proof) — “คนอื่นเขาก็ทำกันแบบนี้”

            🚩 สัญญาณเตือนที่จำง่าย

            • เร่ง + ลับ + ผิดขั้นตอน — ครบสามข้อนี้เมื่อไหร่ให้สงสัยไว้ก่อน
            • ขอ OTP หรือรหัสผ่าน — องค์กรจริงไม่ขอ ไม่ว่าช่องทางใด
            • โดเมนผู้ส่ง สะกดต่างไปเล็กน้อย จากของจริง
            • ลิงก์ที่ ข้อความกับปลายทางไม่ตรงกัน
            • ห้ามตรวจสอบย้อนกลับ เช่น “อย่าโทรหาผม”

            ✅ วิธีรับมือที่ใช้ได้จริง

            • หยุดก่อนคลิก — ความเร่งด่วนคือเครื่องมือของผู้โจมตี
            • ยืนยันผ่านช่องทางที่สอง — โทรกลับด้วยเบอร์ที่เรามีอยู่เดิม ไม่ใช่เบอร์ในอีเมล
            • เปิด MFA ไว้เสมอ เพื่อให้รหัสผ่านที่รั่วไปยังไม่พอ
            • รายงานทันทีเมื่อเผลอกด — แจ้งเร็วเสียหายน้อย ไม่ควรกลัวโดนตำหนิ

            บทที่ 6

            การโจมตีระดับเครือข่าย

            บทนี้ขยายรายละเอียดของการโจมตีที่เจอในบทที่ 3 โดยเน้นตัวที่ออกสอบบ่อยที่สุด — MITM, DoS/DDoS, การดักฟัง, การยึดเซสชัน, DNS ปลอม และการโจมตี Wi-Fi

            Man-in-the-Middle: เทียบการส่งข้อมูลปกติกับตอนถูกดักกลาง

            แบบแรกคือสิ่งที่เคยเห็นในเว็บ Computer Networks — A ส่งถึง B ตรง ๆ แบบที่สองคือเมื่อมีผู้โจมตีแทรกกลาง โดยที่ทั้ง A และ B ยังคิดว่าคุยกันตรง ๆ อยู่

            DoS เทียบกับ DDoS

            การโจมตีเครือข่ายที่ต้องรู้จัก

            เชื่อมกับบทที่ 3: สังเกตว่าการโจมตีเหล่านี้ล้วนระบุชั้นของ OSI ได้ทั้งหมด เมื่อรู้ชั้นก็รู้ทันทีว่าต้องกันที่ไหน — ARP Poisoning และ Rogue DHCP กันที่ สวิตช์ (L2), IP Spoofing กันที่ เราเตอร์ขอบ (L3), SYN Flood กันที่ firewall/อุปกรณ์ anti-DDoS (L4), ส่วน DNS Spoofing และ HTTP Flood กันที่ ระดับบริการและ CDN (L7)
            บทที่ 7

            การโจมตีเว็บและแอปพลิเคชัน

            ทุกช่องโหว่ในบทนี้มีรากเดียวกันคือ “โปรแกรมเชื่อข้อมูลจากภายนอกมากเกินไป” ตัวอย่างโค้ดในหน้านี้เป็นตัวอย่างสมมติเพื่ออธิบายว่าช่องโหว่เกิดจากตรงไหนและปิดอย่างไร ไม่ใช่เครื่องมือที่ใช้โจมตีระบบจริง

            หมายเหตุเพื่อการศึกษา: เว็บนี้อธิบายเฉพาะ หลักการทำงาน และ วิธีป้องกัน โดยตั้งใจไม่แสดง payload ที่ใช้โจมตีได้จริง เพราะเป้าหมายคือให้เข้าใจพอที่จะ “เขียนโค้ดให้ปลอดภัย” และ “ตอบข้อสอบได้” ไม่ใช่เพื่อนำไปใช้กับระบบของผู้อื่น
            บทที่ 8

            Cryptography พื้นฐาน

            วิทยาการเข้ารหัสคือเครื่องมือที่ทำให้ CIA Triad เป็นจริงได้ในทางเทคนิค เริ่มจากแยกสามคำที่คนสับสนมากที่สุดก่อน แล้วค่อยไล่ไปถึงกุญแจคู่ ใบรับรอง และการจับมือของ HTTPS

            Encryption vs Hashing vs Encoding — คนละเรื่องกันทั้งสามอย่าง

            ข้อสอบชอบถามข้อนี้เพราะคนจำนวนมากเข้าใจว่า Base64 คือการเข้ารหัส ซึ่งไม่ใช่

            ประเด็น Encryption (เข้ารหัส) Hashing (แฮช) Encoding (แปลงรูปแบบ)

            Symmetric vs Asymmetric — กุญแจเดียว เทียบกับ กุญแจคู่

              📖 เรื่องที่ต้องจำเกี่ยวกับ TLS

                🔗 โยงกับความรู้ OSI เดิม

                TLS ทำงานคาบเกี่ยวระหว่าง Layer 5 (Session) กับ Layer 6 (Presentation) คือเปิดเซสชันที่ปลอดภัยและจัดการการเข้ารหัส/ถอดรหัส โดยวางตัวอยู่เหนือ Layer 4 (TCP) และให้บริการกับ Layer 7 (HTTP) ด้านบน

                นี่คือเหตุผลว่าทำไม HTTPS จึงไม่ใช่โปรโตคอลใหม่ แต่คือ HTTP ที่วิ่งอยู่ในอุโมงค์ TLS

                บทที่ 9

                การป้องกัน (Defense)

                รู้จักการโจมตีครบแล้ว บทนี้คือฝั่งตรงข้าม — เครื่องมือและแนวทางที่ใช้กัน พร้อมคำตอบว่าแต่ละอย่างต่างกันตรงไหน ซึ่งเป็นจุดที่ข้อสอบชอบถามมากที่สุด

                Firewall: Stateless เทียบกับ Stateful

                ประเด็น Stateless Firewall Stateful Firewall

                ชนิดของ Firewall เรียงตามความลึกที่มองเห็น

                IDS เทียบกับ IPS

                ต่างกันที่ “ตำแหน่งการวาง” และ “สิทธิ์ในการลงมือ” เป็นหลัก

                ประเด็น IDS (Detection) IPS (Prevention)

                VPN เทียบกับ Proxy

                ประเด็น VPN Proxy

                การป้องกันที่เครื่องปลายทางและการจัดการช่องโหว่

                Network Segmentation และ DMZ

                DMZ คือเขตกันชนระหว่างอินเทอร์เน็ตกับเครือข่ายภายใน คลิกที่โซนเพื่อดูรายละเอียด

                Zero Trust

                🏰 แนวคิดเดิมที่ใช้ไม่ได้แล้ว
