บทที่ 1

ภาพรวม: ทำไมต้องมีโมเดลชั้นเครือข่าย

เวลาเราเปิดเว็บสักหน้า มีงานหลายสิบอย่างเกิดขึ้นพร้อมกัน ตั้งแต่การแปลชื่อโดเมนเป็น IP การหาเส้นทาง ไปจนถึงการยิงสัญญาณไฟฟ้าออกไปบนสาย OSI Model คือการจับงานทั้งหมดนั้น มาจัดเป็นชั้น ๆ เพื่อให้เข้าใจ ออกแบบ และแก้ปัญหาได้ทีละส่วน

📚 OSI Model คืออะไร

OSI ย่อมาจาก Open Systems Interconnection เป็นแบบจำลองอ้างอิงที่องค์กร ISO กำหนดขึ้นในปี ค.ศ. 1984 เพื่อใช้อธิบายว่าข้อมูลเดินทางจากโปรแกรมบนเครื่องหนึ่ง ไปถึงโปรแกรมบนอีกเครื่องหนึ่งได้อย่างไร โดยแบ่งกระบวนการทั้งหมดออกเป็น 7 ชั้น

ข้อควรจำ: OSI เป็นแบบจำลอง เชิงอ้างอิง ที่ใช้สอนและใช้สื่อสารกัน ส่วนอินเทอร์เน็ตจริง ๆ ทำงานบนชุดโปรโตคอล TCP/IP

🧩 ทำไมต้องแบ่งเป็นชั้น

  • แยกความรับผิดชอบ — แต่ละชั้นทำงานของตัวเองอย่างเดียว ไม่ก้าวก่ายกัน
  • เปลี่ยนชิ้นส่วนได้อิสระ — เปลี่ยนจากสาย LAN เป็น Wi-Fi (L1–L2) โดยไม่ต้องแก้เบราว์เซอร์ (L7)
  • แก้ปัญหาง่ายขึ้น — ไล่ปัญหาทีละชั้นตั้งแต่สายหลุด (L1) ไปจนถึงเว็บล่ม (L7)
  • ผู้ผลิตต่างเจ้าคุยกันได้ — ยึดมาตรฐานเดียวกัน อุปกรณ์ต่างยี่ห้อจึงทำงานร่วมกันได้
  • เรียนรู้ง่าย — ย่อยเรื่องซับซ้อนเป็นก้อนเล็ก ๆ ที่จำได้

🏠 เปรียบเทียบกับการส่งพัสดุ

ลองนึกถึงการส่งของ: คุณเขียนจดหมาย (L7) ใส่ซองและปิดผนึก (L6) ตกลงกับผู้รับว่าจะส่งเมื่อไหร่ (L5) แบ่งของเป็นหลายกล่องพร้อมเบอร์กล่อง (L4) เขียนที่อยู่บ้านปลายทาง (L3) ส่งต่อให้รถขนส่งคันถัดไปตามจุด (L2) และสุดท้ายรถวิ่งบนถนนจริง (L1)

ฝั่งผู้รับก็แกะย้อนกลับขึ้นมาทีละชั้นจนได้จดหมายฉบับเดิม

OSI Model เทียบกับ TCP/IP Model

TCP/IP เป็นโมเดลที่ใช้งานจริงบนอินเทอร์เน็ต มี 4 ชั้น เกิดขึ้นก่อน OSI ด้วยซ้ำ ความสัมพันธ์ของทั้งสองโมเดลเป็นดังนี้

TCP/IP Model (4 ชั้น) ตรงกับ OSI (7 ชั้น) โปรโตคอลตัวอย่าง หมายเหตุ

⚖️ ความต่างที่มักออกสอบ

  • OSI มี 7 ชั้น / TCP/IP มี 4 ชั้น (บางตำราแบ่งเป็น 5 ชั้น โดยแยก Physical ออกมา)
  • OSI พัฒนาโดย ISO / TCP/IP พัฒนาโดย DARPA (กระทรวงกลาโหมสหรัฐฯ)
  • OSI สร้างโมเดลก่อนแล้วค่อยมีโปรโตคอล / TCP/IP มีโปรโตคอลใช้งานจริงก่อนแล้วจึงสรุปเป็นโมเดล
  • OSI แยกหน้าที่ชัดเจนกว่า เหมาะกับการเรียน / TCP/IP ยืดหยุ่นกว่า จึงถูกใช้งานจริง

🚀 เริ่มติวยังไงดี

  1. ท่องชื่อ 7 ชั้นด้วย mnemonic ให้ขึ้นใจก่อน
  2. จำ PDU ของแต่ละชั้น (Bit / Frame / Packet / Segment / Data)
  3. จำอุปกรณ์ประจำชั้น (Hub=1, Switch=2, Router=3)
  4. ท่องพอร์ตสำคัญ 10 ตัวแรกในหน้า Protocols
  5. ดูแอนิเมชัน Encapsulation ให้เห็นภาพรวม
  6. ลงมือทำ Quiz แล้ววนทวนด้วย Flashcards

บทที่ 5

IPv4, IPv6 & MAC Address

เครือข่ายใช้ที่อยู่สองแบบคู่กันเสมอ — MAC ที่ Layer 2 ไว้ส่งกันในวงเดียวกัน และ IP ที่ Layer 3 ไว้ส่งข้ามเครือข่าย บทนี้แยกให้เห็นชัดว่าใครทำหน้าที่อะไร

IPv4 — โครงสร้าง 32 บิต

🔢 อ่านค่า IPv4 อย่างไร

IPv4 ยาว 32 บิต แบ่งเป็น 4 กลุ่มกลุ่มละ 8 บิต เรียกว่า octet แต่ละ octet เขียนเป็นเลขฐานสิบได้ตั้งแต่ 0 ถึง 255 คั่นด้วยจุด เรียกรูปแบบนี้ว่า dotted decimal notation

8 บิตเก็บค่าได้ 2⁸ = 256 ค่า จึงเป็นเหตุผลว่าทำไมเลขในแต่ละช่องถึงเกิน 255 ไม่ได้

✂️ Network Part กับ Host Part

IP หนึ่งเลขถูกแบ่งเป็นสองส่วนด้วย Subnet Mask คือส่วนที่บอกว่า “อยู่วงไหน” (network) กับส่วนที่บอกว่า “เป็นเครื่องไหนในวงนั้น” (host)

บิตที่เป็น 1 ในซับเน็ตมาสก์คือส่วน network ส่วนบิตที่เป็น 0 คือส่วน host เขียนย่อเป็น CIDR ได้ เช่น 255.255.255.0 เขียนเป็น /24 เพราะมีบิต 1 อยู่ 24 ตัว

🏠 Private กับ Public

Private IP ใช้ได้เฉพาะภายในเครือข่ายของเรา ออกอินเทอร์เน็ตตรง ๆ ไม่ได้ ต้องให้เราเตอร์ทำ NAT แปลงเป็น Public IP ก่อน

นี่คือเหตุผลที่บ้านคุณกับบ้านเพื่อนใช้ 192.168.1.1 เหมือนกันได้โดยไม่ชนกัน

🧮 เครื่องมือแปลง IP เป็นเลขฐานสอง

พิมพ์ IP แล้วดูทันทีว่าแต่ละ octet หน้าตาเป็นเลขฐานสองอย่างไร เลือก prefix เพื่อดูซับเน็ตมาสก์ หมายเลขเครือข่าย และช่วง host ที่ใช้ได้

    MAC Address — ที่อยู่ทางกายภาพ 48 บิต

    MAC Address คือหมายเลขประจำตัวของการ์ดแลนแต่ละใบ ถูกฝังมาจากโรงงาน แบ่งครึ่งเป็นสองท่อน ท่อนแรกบอกยี่ห้อ ท่อนหลังบอกว่าเป็นใบที่เท่าไหร่ของยี่ห้อนั้น

    Network Types & Topology

    แบ่งเครือข่ายได้สองมุม — มุมแรกคือ “ครอบคลุมพื้นที่แค่ไหน” (PAN, LAN, MAN, WAN) อีกมุมคือ “ต่อสายกันแบบไหน” (Bus, Star, Ring, Mesh, Tree)

    แบ่งตามขนาดพื้นที่

    ประเภท พื้นที่ครอบคลุม ความเร็วทั่วไป ใครเป็นเจ้าของ ตัวอย่างการใช้งาน
    เทคนิคจำลำดับขนาด: PAN < LAN < CAN < MAN < WAN ยิ่งพื้นที่กว้างขึ้น ความเร็วยิ่งลดลงและดีเลย์ยิ่งสูงขึ้น เพราะข้อมูลต้องเดินทางไกลและผ่านอุปกรณ์มากขึ้น

    Network Topology — รูปแบบการเชื่อมต่อ

    แต่ละผังมีจุดสัญญาณวิ่งอยู่บนเส้น เพื่อให้เห็นว่าข้อมูลเดินทางไปในลักษณะไหน คลิกที่การ์ดเพื่อกางดูข้อดี ข้อเสีย และงานที่เหมาะ

              • DNS ใช้ทั้ง UDP และ TCP ที่พอร์ต 53 ไม่ใช่ UDP อย่างเดียว
              • FTP พอร์ต 21 คือคำสั่ง พอร์ต 20 คือข้อมูล อย่าจำสลับ
              • TCP/IP ไม่มีชั้น Session และ Presentation เพราะถูกยุบรวมเข้าไปในชั้น Application
              • ARP ตำราส่วนใหญ่จัดไว้ที่ L2 หรือคาบเกี่ยว L2–L3 ให้ดูบริบทของข้อสอบ
              • Switch แยก collision domain ได้ แต่หยุด broadcast ไม่ได้ — มีแต่ Router ที่หยุดได้
              • Access Point อยู่ Layer 2 ไม่ใช่ Layer 1 เพราะมันอ่านและส่งต่อด้วย MAC Address
              • MAC เปลี่ยนทุก hop / IP คงเดิมตลอดทาง อย่าตอบสลับกันเด็ดขาด
              • 169.254.x.x ไม่ใช่ Private IP ปกติ แต่แปลว่า DHCP มีปัญหา
              • Full Mesh ใช้สาย n(n−1)/2 เส้น ไม่ใช่ n เส้น
